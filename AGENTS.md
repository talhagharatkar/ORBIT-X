# Project Rules (AGENTS.md)

## Core Principles

- **Typed Python**: All Python code must use type hints and be checked with `mypy` or equivalent.
- **Modular Architecture**: Code is organized into logical packages (e.g., `simulator`, `models`, `api`, `frontend`). No monolithic scripts.
- **Meaningful Tests**: Every module must have unit tests with clear assertions; integration and end‑to‑end tests are required for critical pipelines.
- **No Magic Numbers**: Configuration values live in YAML/JSON/TOML files or constants with descriptive names.
- **Reproducible Experiments**: Random seeds are fixed and logged; each experiment records git commit, environment, and configuration.
- **Deterministic Seeds**: Wherever stochasticity is used (simulation, model initialization), seeds are set from a central config.
- **Proper Logging**: Use structured JSON logging with request IDs, timestamps, and severity levels.
- **Configuration‑Driven Execution**: All adjustable parameters (simulation, model hyper‑parameters, deployment) are loaded from config files; command‑line flags may override but must be logged.
- **No Fake Benchmarks**: Benchmark results must be generated by running the code; never fabricate or copy‑paste numbers.
- **No Invented Scientific Claims**: All statements about performance, causality, or business impact must be supported by actual experimental evidence.
- **Explicit Data Separation**:
  - Observed telemetry vs. simulated data.
  - LLM reasoning vs. ML inference outputs.
- **LLM‑Only for Interface**: The language model may parse user intent and format responses, but never generates model predictions directly.
- **No Secrets in Git**: API keys, passwords, or any credential must be referenced via environment variables or secret managers, never committed.
- **No Destructive Shell Commands Without Confirmation**: Commands that modify the system (e.g., `rm -rf`, database resets) require explicit user confirmation.
- **No Silent Dependency Upgrades**: Dependencies are pinned; upgrades must be reviewed and committed deliberately.
- **No Unverified Claims in Documentation**: Docs must reflect actual implementation and experimental results.
- **Machine‑Readable Results**: Every experiment produces JSON/CSV artifacts that can be parsed programmatically.
- **Metric Generation**: Model metrics (MAE, RMSE, calibration, etc.) are computed by the code and stored; they are not handwritten.

These rules are enforced by automated linting, CI checks, and periodic audits.
